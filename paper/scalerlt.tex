\begin{abstract}
Recurrent looped transformers reuse physical parameters while retaining distinct computational states for each invocation. Reinforcement learning adds repeated prompt groups, sampled trajectories, reference evaluation, optimizer state, and policy publication to this execution graph. ScaleRLT investigates an I/O-aware execution layer that treats these dependencies explicitly. Its design combines response-position readout, bounded output export, stage-aware key--value allocation, and joint loop--sequence rematerialization with differentiable prefix reuse. The primary endpoint is time and allocated GPU-hours to held-out reward quality, supported by matched-workload throughput and memory measurements. This manuscript is an evolving research artifact: prior short-run validation is identified separately, and the proposed system's complete performance and convergence evaluation remains unfinished. No unmeasured speedup or quality improvement is claimed.
\end{abstract}

\section{Introduction}
Parameter sharing changes the economics of transformer execution. A recurrent core is stored once, yet a token may invoke it many times. Recurrent depth therefore measures computation, not unique parameter count. During reinforcement learning (RL), each invocation also contributes to an explicitly chosen gradient contract. Optimizing inference alone does not establish an improvement in complete RL updates.

We study the following question: can execution scheduling reduce memory traffic and resident state while preserving a declared looped policy and its gradients, and can those gains reduce the cost of reaching a fixed reward quality? Our starting point is the existing VIME native backend and vllm-rlt integration, including physical parameter sharing, recurrent traces, policy publication, and checkpoint recovery~\cite{vime,rlt}. These capabilities are inherited infrastructure, not new contributions of this work.

Three distinctions govern the evaluation. First, exact execution and approximate policies require separate comparisons. Second, fixed-workload timing and natural online learning answer different questions. Third, a three-update recovery test verifies lifecycle correctness; it does not establish reward convergence. The experimental plan tracks each distinction explicitly.

\section{Execution and Learning Contracts}
Let $\theta$ denote unique physical parameters, $r\in\{1,\ldots,R\}$ a recurrent invocation, and $i,t$ a trajectory and response position. A looped actor exposes
\begin{equation}
 \ell_{i,t,r}=\log p_\theta^{(r)}(y_{i,t}\mid x_i,y_{i,<t}).
\end{equation}
For a declared reduction $\mathcal{R}$, the RLTT-style policy-gradient objective is
\begin{equation}
 L_{\rm PG}=-\mathcal{R}_{i,t}\left[\hat A_i\sum_{r=1}^{R}w_{i,t,r}\ell_{i,t,r}\right].
\end{equation}
The weighted sum of log probabilities differs from the log of a mixture. The public RLTT loss uses a masked token mean and an unclipped policy-gradient surrogate~\cite{rltt}; reproducing its actor accumulation requires auditing the surrounding microbatch and update schedule as well. We distinguish a source-matched reproduction from a separately specified objective reimplementation.

A frozen reference has its own immutable policy identity. Sampled KL estimators and full-vocabulary KL are separate profiles. For dynamic credit weights, whether gradients traverse $w$ is independent of whether the exit-head parameters are trainable. These choices enter the experiment manifest alongside dtype, optimizer, reduction denominator, and the number of actual optimizer steps per rollout batch.

\subsection{State and provenance}
An execution node is identified by policy, model family, physical layer, loop, sequence or prefix, token range, and execution profile. Distinct loop invocations retain distinct hidden and KV dependencies even when they share weights. A sampled trace records response-aligned depth, raw or processed scoring semantics, sampling transformations, termination reason, latent seed, and the committed publication digest.

Huginn additionally requires latent identity: equal text does not imply an equal recurrent prefix. Reusing deterministic prelude work and reusing a complete latent-conditioned prefix are different operations. The first response token is predicted at the final prompt position; this boundary must survive every readout and prefix transformation.

\section{I/O-Aware Execution}
\subsection{Terminal output export}
The inherited offline generation path repeatedly constructs cumulative output objects, although its caller consumes only completed requests. For $T$ generated tokens, cumulative selected-score exports can contain
\begin{equation}
 \sum_{t=1}^{T}t=\frac{T(T+1)}{2}
\end{equation}
elements. A terminal-output path exports $T$ scores once. This is a count of materialized elements, not a predicted end-to-end speedup. The implementation preserves tokens, depths, processed scores, policy versions, stop conditions, cancellation, and speculative acceptance ordering. Streaming retains its existing cumulative interface. Ouro-1.4B GPU asynchronous delivery is qualified below; other model families and longer-running workloads remain pending.

\subsection{Stage-aware KV residency}
KV allocation follows the model's actual stages. If prelude and coda execute once while the core executes $R$ times, the required logical layer planes are
\begin{equation}
 N_{\rm KV}=L_{\rm pre}+R L_{\rm core}+L_{\rm post}.
\end{equation}
For the Huginn R32 profile this yields $2+4\cdot32+2=132$ planes, compared with $8\cdot32=256$ in a rectangular layout. The opt-in implementation allocates separate core and boundary pools. A page bundle owns $R$ core pages and one boundary page; admission, growth and release operate on complete bundles. Explicit byte budgets round down by the exact integer bundle size. Tiny CPU allocations verify the corresponding $48.44\%$ reduction in KV tensor storage. GPU allocator peaks, graph pools, total training memory, and measured GPU capacity remain to be evaluated.

\subsection{Response readout and exact reductions}
The output head should consume only hidden positions needed by the objective. Vocabulary tiling can compute selected-token scores using an exact log-sum-exp without retaining a complete loop--token--vocabulary tensor. Full-distribution objectives still require the full normalization and reduction:
\begin{equation}
 D_{\rm KL}(p\Vert q)=\sum_v p_v(\log p_v-\log q_v).
\end{equation}
Replacing this expression with selected-token or top-$k$ scores changes the objective. Forward and backward comparisons therefore include every physical parameter and any trainable credit weights.

\subsection{Joint rematerialization and prefix gradients}
The current prototype enumerates loop and layer checkpoint intervals and token query chunks. Response reductions execute inside loop checkpoints; token chunks retain their complete causal KV prefixes and corresponding gradients. Its selector considers only measured, gradient-verified records for the same workload, timing scope and memory metric. CPU saved-storage observations cannot substitute for CUDA peaks. Readout tiles are separately configurable; extending the joint search to prefix-residency counts and sharded weight-residency windows remains planned.

For a shared prefix state $z$, differentiable reuse has the form
\begin{equation}
 g_\theta=\sum_i g_{\theta,{\rm suffix}_i}
       +J_{\theta,z}^{\mathsf T}\sum_i g_{z,i}.
\end{equation}
Here $z$ contains every loop and stage KV boundary plus readout and other cross-boundary states. Accumulating only KV adjoints misses direct first-response readout gradients. All suffixes use the logical batch denominator, and parameters remain unchanged until their complete aggregate update. The ordinary three-phase prefix schedule follows prior work~\cite{prefix}. The loop-specific planner must improve upon both standard rematerialization and a generic shared-prefix baseline to support a distinct scheduling contribution.

\section{Evaluation Protocol}
\subsection{Baselines and models}
Training comparisons retain native VIME/Megatron, a declared RLTT reproduction or reimplementation, standard batching/readout/checkpoint optimizations, and generic prefix reuse. Slime and Megatron are additional framework baselines whose actual looped-model capability and version must be verified. Serving comparisons include FlashLoop dense and full-method configurations in their common supported domain, plus the existing optimized vllm-rlt path. Unsupported configurations are reported as such rather than assigned zero throughput.

The core matrix comprises Ouro 1.4B and 2.6B, Nanbeige4.2, and Huginn-0125. IQuest 40B is a separate extension with an explicit full-update resource gate. Parameter counts refer to unique checkpoint tensors; expanded loop depth is not additional physical model size.

\subsection{Three complementary experiments}
Fixed-trace update experiments hold tokens, depth, advantages, reference values, and reduction fixed. Serving experiments hold the prompt and completion workload fixed and report actual concurrency, queue delay, TTFT, TPOT, failures, and memory. Fresh online RL allows natural termination and records reward, response lengths, policy staleness, and all lifecycle phases.

Complete RL wall time includes rollout, reward, reference or critic, actor, publication, and scheduled checkpoint work. Overlapping phases are measured on the actual critical path. Resource cost is
\begin{equation}
 {\rm GPUh}=\frac{1}{3600}\sum_{j\in\mathcal{G}}\text{allocated device-seconds}_j.
\end{equation}
Co-located actor and rollout roles do not double-count one GPU; allocated idle devices are still included.

\subsection{Reward as the primary endpoint}
Before formal runs, the held-out split, reward implementation, sampling budget, noninferiority tolerance, and target quality are frozen. Main quality conclusions require at least three independent training seeds and uncertainty across held-out items. We record mixed-reward group frequency, advantage variance, KL, entropy, gradient norm, parameter delta, and optimizer updates. Zero-advantage groups cannot demonstrate learning merely by incrementing a policy version.

Paired timing comparisons use independent process restarts and confidence intervals clustered by run. Repeated steps within one run do not substitute for independent training seeds. OOM, numerical failure, unsupported profiles, and unrun experiments remain visible in separate rows.

\subsection{Existing rollout prefix reuse}
Before adding group-fork scheduling, we measure the inherited full-page prefix cache on tiny Ouro and Nanbeige models. Eight equal prompts arrive together with distinct completion seeds. At actual concurrency eight, a cold engine admits all requests before any prefix becomes available, so the group records zero reused tokens. At concurrency four, a later admission wave reuses earlier pages; at concurrency one, reuse occurs across successive requests. With a pre-existing cache all requests can hit. This identifies a cold group-admission gap without attributing existing reuse to ScaleRLT.

Partial tails are copied on their first continuation write; admission reserves their capacity and can reclaim pending snapshots in favor of recomputation. Forks obey bounded admission bypass. \subsection{Training bridge and recovery}
The current training branch uses static uniform or progressive credit, terminal sampled k3, and a frozen initial reference, including when the KL coefficient is zero. Reference replacement is rejected. It computes the logical-step reduction before partitioning microbatches and compensates the actual MCore schedule's loss divisor. Twelve numerical configurations span three families, two reductions, and recomputation on/off; each checks three microbatch partitions against an independent dense gradient oracle. Full-vocabulary KL and learned exit credit are not yet connected to this online branch.

For each family, a tiny native engine generates fresh groups, an output-derived token-parity reward supplies GRPO advantages, and AdamW performs three nonzero updates. Physical policy publication and fresh actor/reference/optimizer recovery reproduce the third update exactly. Maximum rollout/replay score errors are $2.38\cdot10^{-7}$ (Ouro), $4.77\cdot10^{-7}$ (Nanbeige), and $1.91\cdot10^{-6}$ (Huginn). These CPU component cycles exercise real sampling and optimization but do not run Ray workers, GPU DDP, distributed checkpointing, or a reasoning benchmark. Their short reward sequences are not convergence evidence.

The combined run contains 257 passing checks and three import failures caused by unavailable Triton; failed factory checks are retained and excluded from the pass count. CPU tests use MCore commit 1dcf0da with VIME's standard patch. All 2232 files of the tested tree independently match its pinned patched-source manifest. The separate upstream Megatron baseline archive does not supply this test runtime.

\subsection{Logical-step scaling and unresolved BF16 updates}
The ordinary MCore schedule divides each microbatch loss by the microbatch count. Its existing RLTT adapter compensates with the inverse factor. The prefix path instead consumes the unscaled logical objective, applies optimizer loss scaling once per suffix backward, and injects already-scaled boundary adjoints without a second factor. A logical-step plan retains original sample and GRPO group identities while grouping compatible Ouro prompts; empty and masked responses retain their global weights.

Twelve FP32 CPU configurations each execute two AdamW updates, comparing independent dense depth replays with the actual MCore loss/backward functions and the prefix components. Both reductions, reordered microbatches, ragged suffix waves and loss scales one/eight are covered. Maximum full-gradient relative L2 error is $5.38\times10^{-7}$ and maximum parameter-delta error is $1.20\times10^{-7}$. The frozen reference differs from the actor. These tests do not instantiate a GPU DDP or mixed-precision optimizer wrapper.

The corresponding twelve CPU BF16 configurations remain unqualified under unchanged tolerances: all 24 update observations fail the parameter-delta gate, and six also fail the later gradient gate. Maximum gradient relative L2 error is $2.74\times10^{-2}$ and delta error is $1.77\times10^{-3}$. Both-update records and initial failures are retained. The FP32 production schedule has since passed the small real-MCore CUDA control below; this does not qualify BF16 or official online learning.
